The promise library

One witness. Four promises.

The ad can promise a shipping threshold, a percentage discount, a bundle or a delivery date. Kern gives each one a boundary case and a control.

01 · Shipping

$50 threshold

$60 and the exact $50 qualify; the $35 control keeps paying $9.

02 · Percentage

20% over $50

$60 gets $12 off; the exact boundary gets $10; the $35 control gets $0.

03 · Bundle

Tote + notebook

The complete bundle gets 15%; tote-only and notebook-only get $0.

04 · Delivery

2pm / 2 days

The cutoff and weekends move the date: Nov 30, Dec 1, Dec 2.

The product

A promise firewall for AI-generated commerce changes.

Most tests check whether the code still works. Kern checks whether the customer still gets what the ad promised.

01

Four promise classes

Free shipping, percentage discounts, bundles and delivery estimates. One witness, one boundary-and-control discipline.

02

Frozen promise contract

The ad and the merchant’s interpretation stay separate. The terms and policy are hash-linked before a run.

03

Kane in the real checkout

Kane reads the rendered price, discount, bundle total or delivery date. The store’s own code never decides whether the promise passed.

04

Boundary + control

Every class gets an eligible case, the exact edge and a control. The offer cannot be “fixed” by giving it to everyone.

05

An agent gate, not a report

The gate exits non-zero. Claude Code can stop-block; Pi can run the same command. The agent cannot self-certify.

06

Scoped promise proof

The promise, observed values, evidence hashes, code change and “what this does not prove” live in one record.

The witness

Kane CLI is not a checkbox at the end.

Kane is the only component that opens the customer checkout and reads the rendered value. Kern freezes the promise and decides; Kane supplies the independent browser truth.

01

It sees the checkout

A unit test can agree with the bug. Kane reads the actual rendered price, discount, bundle total or delivery date the customer sees.

02

It carries the evidence

Every run has a terminal run_end, exit code, extracted values and evidence hash. The gate is built on those artifacts.

03

It gates the repair

Pi can change the source, but not the challenge. Kane reruns the same objectives after a change before the gate can open.
